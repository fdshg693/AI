# 複数ファイル並列AIプロンプト投げツール（aim-ask）

## 問題設定

- `aim-summarize` はリポジトリ全体をファイル単位で要約しDBに保存する用途に特化しており、任意の質問プロンプトをその場で複数ファイルに投げて結果だけ受け取りたい、というワンショットな用途には合わない
- DB永続化・ハッシュベースの再生成スキップ・`.gitignore` 尊重といった仕組みは、ワンショット用途には過剰

## 解決策

- 指定した複数ファイルに対して、同一のプロンプト（デフォルトは要約プロンプト、`--prompt` で動的に上書き可能）を1ファイルにつき1回のAI呼び出しで並列に投げる
- DBには保存せず、全ファイルの結果が揃った時点でパスと応答の対応が明確な配列として標準出力に返す

## 全体方針（決定事項）

| 論点                             | 決定                                                                                                                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実装形態                         | 独立CLIツール（`aim` CLI を基盤とした `aim-use` 配下の新規パッケージ）                                                                                                             |
| 永続化                           | なし（ステートレス。実行のたびに結果を返すのみ）                                                                                                                                   |
| プロンプトのファイル単位の可変性 | ファイルごとに変化させない。全ファイルに同一の文字列を使う（ファイルパスをプロンプト文言に埋め込まない）                                                                           |
| デフォルトプロンプトの定義場所   | 専用設定ファイル `.aim-use/aim-ask.toml`（`aim-summarize` の `config.toml` とは別ファイル）。省略可能で、無ければ組み込みデフォルトを使う                                          |
| プロンプトの動的上書き           | `--prompt` CLI引数で上書き可能。優先順位は CLI引数 > 設定ファイル > 組み込みデフォルト                                                                                             |
| 並列実行                         | 1ファイルにつき1回のAI呼び出し。複数ファイルをまとめて1回の呼び出しにはしない。`asyncio.Semaphore` による同時実行数制御（`jobs`、1〜10、デフォルト4）                              |
| リトライ                         | AI呼び出し失敗時は1回までリトライ。それでも失敗したらそのファイルだけ失敗として記録し、他ファイルの処理は継続する                                                                  |
| 対象外ファイルの扱い             | 存在しないパス・単一指定のバイナリ/デコード不能ファイルは、そのパスだけ失敗として記録し処理を継続する。ディレクトリ指定時は配下のバイナリ/デコード不能ファイルを個別にスキップする |
| 出力形式                         | Markdown をデフォルトとし、`--format json` にも対応（`aim-summarize get` と同じ流儀）                                                                                              |
| 結果の対応付け                   | 各結果に `path`（CLI引数の文字列そのまま）と `resolved_path`（CWD基準で解決した絶対パス）の両方を持たせ、応答とファイルの対応を常に明確にする                                      |

## ディレクトリ構成

`tools/aim-use/aim-summarize` と同じパターンで、`tools/aim-use` 配下に専用パッケージとして配置する。

```
tools/aim-use/
└── aim-ask/
    ├── README.md
    ├── PLAN.md                # 本ファイル
    ├── pyproject.toml         # console script: aim-ask
    ├── .gitignore
    ├── config.toml.example    # .aim-use/aim-ask.toml としてコピーするサンプル（省略可）
    └── aim_ask/
        ├── __init__.py
        ├── cli.py             # argparseエントリポイント
        ├── config.py          # .aim-use/aim-ask.toml の探索・読み込み（省略可。無くてもエラーにしない）
        ├── asker.py           # aim CLI呼び出し（非同期）+ デフォルトプロンプト定義
        └── formatter.py       # markdown / json 整形
```

## `aim-summarize` との主な差分

- 設定ファイルが見つからなくてもエラーにせず、組み込みデフォルトにフォールバックする（`aim-summarize` は `.aim-use/config.toml` が必須）
- `.gitignore` 尊重やファイルサイズ上限・include/exclude正規表現によるスキャンは行わない。CLI引数で渡されたパスのみを対象とする
- プロンプトテンプレートにファイルパスを埋め込まない（要件「プロンプトはファイル単位で変わらない」を厳密に満たすため）
- SQLite DBへの保存を行わない。結果は毎回の実行で標準出力に返すのみ

## ディレクトリ入力

- パスにディレクトリを指定した場合は、除外ディレクトリ（`.git`、`__pycache__`、`node_modules`、`.venv`、`venv`）を除く相対パスのツリー listing と、各ファイルの内容を1つのテキストにまとめる
- ディレクトリも1パスとして扱い、フォルダ全体に対してAI呼び出しを1回だけ行う。複数パスを指定した場合の並列実行モデルは変えない
- バイナリまたはUTF-8として読めないファイルは、ツリー listing に「読み込みスキップ」の注記を残し、内容だけをAI入力から除外する
- 総サイズの上限や切り詰めは設けない。大きなディレクトリでは入力が大きくなり得るため、用途は小規模なスキルフォルダを想定する
