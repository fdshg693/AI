# aim-cli スキルについて

`tools/aim/`の`aim` CLI（OpenRouter経由でAIモデルを単発呼び出しするツール）を、Claudeが会話の中からすぐ使えるようにするためのスキル。このファイルは人間のメンテナ向けで、設計意図と前提条件を説明する。Claudeが実行時に読むのは[SKILL.md](SKILL.md)であり、こちらは参照しない。

## なぜこのスキルがあるか

- `aim`はエージェント機能を持たない単発呼び出し専用CLIで、モデル一覧や使い方を都度`tools/aim/README.md`から読み解くのは冗長
- 「どのモデルをデフォルトにするか」「どのタスクでどのモデルにエスカレーションするか」は`tools/aim/README.md`には書かれていない運用ポリシーであり、それを判断ロジックとして固定化するためにスキル化した

## 前提条件（重要）

- `aim`コマンドは事前にインストール済みであること（`uv tool install --editable tools/aim`）。このスキルはインストール処理を一切行わず、CLI本体も同梱しない
- `OPENROUTER_API_KEY`が環境変数または`tools/aim/.env`で設定済みであること
- 上記が満たされていない環境（未インストール・APIキー未設定）でこのスキルが呼ばれた場合、Claudeはこのスキルではエラーに対処せず、`tools/aim/README.md`のセットアップ手順をユーザーに案内する

## 情報源と保守

- CLIオプション・ログ形式・エラー挙動の一次情報は`tools/aim/README.md`
- SKILL.mdはClaudeが実行時に外部ファイルへジャンプしなくて済むよう、上記の内容を意図的に自己完結する形で複製している。`tools/aim/README.md`側（オプション名・利用可能モデル一覧など）が変わった場合はSKILL.mdも合わせて更新すること
- モデル選択ポリシー（デフォルト`minimax-m3`、簡単なタスクは`gpt-oss-120b`、高精度が必要な場合は`glm-5.2`/`gpt-5.6-luna`にエスカレーション）はこのスキル固有の運用方針であり、`tools/aim/README.md`には存在しない

二重化した内容のドリフトを防ぐため、CLI仕様を変更するときは次の順で確認する。

1. `tools/aim/README.md`を正本として、CLI本体と仕様を更新する
2. `SKILL.md`の「前提条件」「使い方」「ログ」「エラー時の挙動」を同じ変更内容に更新する
3. モデル一覧・オプション名・ログ項目・終了条件を両ファイルで突き合わせる
