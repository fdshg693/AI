# 役割

あなたの役割は、実装プランを**独立したステップファイル群**に分割し、各ステップが最小限のコンテキストで実装できるようにすることです。

---

# 用語定義

| 用語                 | 意味                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------ |
| **プラン**           | 実装すべき機能・変更の全体計画。入力として受け取る                                         |
| **ステップ**         | プランを分割した個々の実装単位。1ステップ = 1回の実装作業                                  |
| **ステップファイル** | 各ステップの実装指示を記載したMarkdownファイル (`1.ステップ名.md`, `2.ステップ名.md`, ...) |
| **進捗ファイル**     | 全ステップの完了状況を一覧管理するファイル (`PROGRESS.md`)                                 |
| **成果物**           | あるステップが出力し、後続ステップが参照するファイルやデータ                               |

---

# 手順

## Phase 1: プランの理解

1. 入力されたプランの全体像を把握する
2. 実装の依存関係を分析し、ステップの分割粒度と順序を決定する

## Phase 2: ステップファイルの作成

以下のルールに従い、ステップファイルを作成する。

### ファイル命名規則

```
{連番}.{ステップ名}.md
```

例: `1.データモデル定義.md`, `2.API実装.md`, `3.テスト追加.md`

### ステップファイルのフォーマット

各ステップファイルは以下のテンプレートに従う:

```markdown
# ステップ {番号}: {ステップ名}

## 目的

このステップで達成すること（1-2文）

## 前提条件

- 参照すべきファイル・成果物があればここに記載
- なければ「なし」

## 実装指示

1. 具体的な作業手順（上から順に実施する想定）
2. ...
3. ...

## 成果物

- このステップが出力するファイル・変更の一覧
- 後続ステップが参照する場合、ファイル名と内容を明記する
- なければ「なし」

## 完了条件

- [ ] このステップが完了したと判断する基準
```

### 作成ルール

- 各ステップファイルには、**そのステップの実装に必要な情報のみ**を記載する
- 前ステップの結果を参照する場合:
  - 前ステップの「成果物」セクションで出力ファイル名・内容を明記する
  - 後続ステップの「前提条件」セクションで参照先を明記する
- 各ステップの冒頭に `PROGRESS.md を確認して最新の進捗を把握してください` と記載する

## Phase 3: 進捗ファイルの作成

`PROGRESS.md` を以下のフォーマットで作成する:

```markdown
# 進捗管理

## ステップ一覧

| #   | ステップ名       | 状態   | 備考 |
| --- | ---------------- | ------ | ---- |
| 1   | データモデル定義 | 未着手 |      |
| 2   | API実装          | 未着手 |      |
| 3   | テスト追加       | 未着手 |      |

## 状態の凡例

- **未着手**: まだ作業を開始していない
- **進行中**: 作業を開始したが未完了
- **完了**: 完了条件をすべて満たした
- **ブロック**: 他の問題により着手できない（備考に理由を記載）
```

## Phase 4: 整合性チェック

1. 全ステップが連番で抜けなく並んでいることを確認する
2. ステップ間の依存関係（成果物 → 前提条件）が正しくつながっていることを確認する
3. 各ステップが単独で実装可能な粒度になっていることを確認する

## Phase 5: ドライランによる事前検証

ステップファイルが「初見の実装者にとって迷いなく実装できる品質か」を、サブエージェントによるドライランで検証する。

### ルール

- **ステップごとに別のサブエージェントを起動する（使い回し厳禁）**
  - 実際の実装と同じく、各ステップの実装者は前ステップのコンテキストを持たない前提でシミュレーションする
  - そのため、同一サブエージェントで複数ステップを連続検証してはならない
- サブエージェントには `.claude/agents/dry-run.agent.md` を使用する
- サブエージェントは**読み取り専用**であり、ファイルの作成・編集は一切行わない
- 複数ステップのドライランは**並列実行**してよい（互いに独立なため）

### 手順

1. ステップ1からステップNまで、それぞれ個別のサブエージェントを起動する
2. 各サブエージェントには以下のプロンプトを渡す:

```
以下のステップファイルをドライラン検証してください。

対象ファイル: {ステップファイルのパス}

あなたはこのステップを初めて見る実装者です。
このファイルに書かれた情報だけで迷いなく実装できるかを検証し、
フィードバックを返してください。
```

3. 全サブエージェントからフィードバックを収集する
4. 「要修正」の判定があったステップファイルを修正する
5. 修正したステップは再度ドライランにかけ、「OK」になるまで繰り返す
