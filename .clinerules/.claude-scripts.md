# hooks_manager — `.claude/settings.json` の hooks を手書きしないための仕組み

## なぜ存在するか

`.claude/hooks/` にフックスクリプトを置くだけでは有効にならず、これまでは有効化のたびに `.claude/settings.json` の `"hooks"` キーを毎回手動で書き写す運用になっていた。フックスクリプト側のdocstringには元々「settings.jsonに書くべきJSON例」がコメントとして書かれていたが、あくまで人間がコピペする前提のドキュメントで、実際の `settings.json` と同期している保証がなかった。

この仕組みは、フックスクリプト自身が「自分がどのイベントにどう登録されるべきか」を機械可読な契約として持ち、それを

1. 一覧・有効/無効を管理する中間ファイル（`hooks.yml`）
2. 実際に読み込まれる `settings.json`

の2段階に自動で反映することで、手書き・手動同期をなくす。

## 全体の流れ

```
.claude/hooks/*.py の <hooks> 契約
        │  sync
        ▼
.claude/scripts/hooks.yml   ← ここで enabled: true/false を人間が編集する
        │  reflect
        ▼
.claude/settings.json の "hooks" キー
```

- **sync**: `.claude/hooks/*.py`（`tests/` 配下は除外）を走査し、`<hooks>` 契約を持つスクリプトを `hooks.yml` に反映する。`description` / `event` / `matcher` / `hook` は契約の内容で常に上書きされるが、`enabled` は既存の値を保持する（新規追加時は `false`）。対応するスクリプトが消えたエントリは自動削除される。
- **reflect**: `hooks.yml` のうち `enabled: true` のエントリだけを `settings.json` の `"hooks"` キーに書き込む（キー全体を上書き）。`enabledPlugins` など他の設定は変更しない。

`hooks.yml` は**生成ファイル**として扱う（sync実行のたびに内容が上書きされる）。唯一手で編集してよいのは各エントリの `enabled` フィールドだけ。

## 使い方

```bash
just sync      # .claude/hooks/*.py の契約を hooks.yml に反映
just reflect   # hooks.yml の有効なフックを settings.json に反映
just update    # sync してから reflect（新しい/変更されたフックを取り込みつつ、有効なものを反映）
```

`just` を使わない場合は直接:

```bash
uv run hooks_manager.py sync
uv run hooks_manager.py reflect
```

`hooks_manager.py`は`pyyaml`に依存するが、素の`python`コマンドには入っていないことがある。ファイル先頭のPEP 723インラインスクリプトメタデータ（`# /// script` ブロック）で依存を宣言しているため、`uv run`経由で実行すれば環境を問わず自動解決される。**`python hooks_manager.py ...`のようにbare pythonで直接実行しない**（`ModuleNotFoundError: No module named 'yaml'`になり得る。過去にこれで無関係な`.venv`を探して回避した事例があり、それ自体が問題だった）。

### 既存のフックを有効化する

1. `hooks.yml` を開き、対象スクリプトの `enabled: false` を `enabled: true` に変更
2. `just reflect`

### 新しいフックスクリプトを追加する

1. `.claude/hooks/` に `.py` ファイルを置く
2. ファイル**先頭のモジュールdocstring**（`#!/usr/bin/env python3` の次に来る最初の `"""..."""`）の中に `<hooks>...</hooks>` タグでYAML契約を書く（下記「契約の書き方」参照）
3. `just sync` → `hooks.yml` に `enabled: false` で追加される
4. 必要なら `hooks.yml` で `enabled: true` にして `just reflect`

契約を持たないスクリプト（`_hook_log.py` のような共有ヘルパーなど）は sync が黙ってスキップする。また `.claude/hooks/tests/` 配下は検証用スクリプト専用で sync の走査対象外（契約を書いても拾われない）。

## 契約の書き方（`<hooks>` ブロック）

モジュールdocstringの中に、次の形式のYAMLを `<hooks>` / `</hooks>` で囲んで書く。1ブロック = 1フック登録（1つのevent・matcher・hookのみ）。

```python
#!/usr/bin/env python3
"""<hooks>
description: 閾値を超えた、巨大ファイルを読み込む際に警告を表示するフックの設定
event: PreToolUse
matcher: Read
hook:
  type: command
  command: python
  args: ["${CLAUDE_PROJECT_DIR}/.claude/hooks/block_large_read.py"]
</hooks>

（ここに通常の英語docstring説明を続けてよい）
"""
```

| フィールド    | 必須           | 説明                                                                                                                                   |
| ------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `description` | ○              | `hooks.yml` に表示される、このフックが何をするかの日本語説明                                                                           |
| `event`       | ○              | フックイベント名（`PreToolUse` 等）。既知のイベント名以外は sync がエラーにする                                                        |
| `matcher`     | イベントによる | 対象を絞るマッチャー。`UserPromptSubmit` など matcher 非対応のイベントでは**省略する**（付けると sync がエラーにする）                 |
| `hook`        | ○              | `settings.json` の `hooks[event][].hooks[]` にそのまま書き込まれるオブジェクト（`type` は必須。`type: command` なら `command` も必須） |

### 1スクリプトを複数イベントに登録する

同じスクリプトを複数のevent（例: 成功時の`PostToolUse`と失敗時の`PostToolUseFailure`）に登録したい場合、docstring中に `<hooks>...</hooks>` ブロックを**複数**並べてよい。

```python
#!/usr/bin/env python3
"""<hooks>
description: ツール呼び出し成功時の処理
event: PostToolUse
matcher: "*"
hook:
  type: command
  command: python
  args: ["${CLAUDE_PROJECT_DIR}/.claude/hooks/example.py"]
</hooks>
<hooks>
description: ツール呼び出し失敗時の処理
event: PostToolUseFailure
matcher: "*"
hook:
  type: command
  command: python
  args: ["${CLAUDE_PROJECT_DIR}/.claude/hooks/example.py"]
</hooks>

（実際にどちらのeventで呼ばれたかはstdinペイロードの`hook_event_name`で判定する）
"""
```

この場合、`hooks.yml` には `example.py#PostToolUse` / `example.py#PostToolUseFailure` のように `<ファイル名>#<event>` をキーとしたエントリが**それぞれ**追加される（`enabled`もエントリごとに個別に管理する）。ブロックが1つだけのスクリプトは従来通りファイル名がそのままキーになる。同一ファイル内で同じeventのブロックを2つ書くとsyncがエラーにする。

マッチャーの評価ルール（完全一致 or 正規表現になる文字種の違いなど）は `claude-plugins/meta/skills/writing-hooks/hooks.md` を参照。

## エラー時の挙動

- `sync`: いずれかのスクリプトの契約が不正（未知の `event`、必須キー欠落など）だと、該当ファイル名を含むエラーを出して**全体を中断**する。他が正常でも `hooks.yml` は一切書き換わらない。
- `reflect`: `hooks.yml` の内容が不正だと同様にエラーで中断し、`settings.json` は書き換わらない。
- どちらも変更がなければファイルへの書き込み自体を行わない（差分なし・冪等）。

## ファイル構成

```
.claude/scripts/
├── README.md          # 本ファイル
├── justfile            # sync/reflect/update のショートカット
├── hooks_manager.py     # sync/reflect の実装
└── hooks.yml             # 生成ファイル（enabledフィールドのみ手動編集）
```
