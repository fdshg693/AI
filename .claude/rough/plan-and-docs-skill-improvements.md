# ラフメモ: プラン運用 & claude-code-docsスキルの改善候補

sandbox-agentプランのstep2実装中に気づいた、プロセス・ツール側の改善候補。今すぐ調査・実装するものではなく、後で直すためのメモ。

## 1. `.claude/plans` 運用: 決定事項の後続ステップへの伝播漏れ

- `01-research.md`が決定事項を覆す調査結果を出したとき、`00-overview.md`は更新されていたが、実際にその決定を使う`02-docker-image.md`側は古い記述のまま残っていた（Node.js必須という誤った前提、`allowedDomains`をproject設定に書く前提、ベースOS未定のまま等）。
- 実装時に自分で気づいて`02-docker-image.md`を直接修正したが、本来はresearchステップ完了時点で「この決定を参照している後続ステップ一覧」を洗い出して全部更新するところまでやるべきだった。
- 改善案（要検討）:
  - `01-research-step-example.md`（テンプレート）に「決定事項が変わったら、参照している後続ステップファイルもこの場で全部更新する」という一文を足す。
  - または`00-overview.md`の決定事項テーブルに「この決定を参照しているステップファイル」列を持たせ、更新漏れを機械的にチェックしやすくする。

## 2. 事前調査ステップ: 「このユースケース固有の組み合わせ」を見落としやすい

- `01-research.md`は`bypassPermissions`下のネットワーク自動承認挙動など、一般的な仕様は深く調べていた。
- しかし「Dockerコンテナの中でClaude Code組み込みサンドボックス（bubblewrap）を動かす」という、**このプロジェクト固有の構成**そのものに関わる論点（非特権コンテナ内で`/proc`を再マウントできず起動失敗しうる、`enableWeakerNestedSandbox`が必要）は事前調査で拾えていなかった。実装時にDockerfileを書きながら公式ページを読み直して初めて見つけた。
- 改善案（要検討）:
  - 事前調査ステップのチェックリストに「一般的な仕様だけでなく、"このユースケースの組み合わせ"（今回なら"コンテナ内実行"）に関する記述が公式ドキュメントにないか」を明示的に確認する項目を足す。

## 3. `claude-code-docs`スキル: 巨大ページのgrepが弱い

- `env-vars.txt`のような大きいページはReadの256KB上限に引っかかりRead不可。Grepでフォールバックしたが、ヒット行がほぼ`[Omitted long context line]`になっていて実質情報が取れなかった。
- これは表示上の省略ではなく、**キャッシュ生成（ダウンロード/抽出）スクリプト自体が長い行を潰して保存している**ように見えた。環境変数一覧・許可ドメイン一覧のような表形式の内容がまさに一番欲しい情報なので、ここが失われるのは実害がある。
- 改善案（要検討）:
  - `download_claude_code_reference.py` / 抽出スクリプト側で、長い行を省略するのではなく折り返す・分割するなど、情報を落とさない形式に変える。
  - もしくは大きいページ用に「表だけを別ファイルに抽出する」等の専用処理を足す。

## 4. `claude-code-docs`スキル: grep先行 vs 全文読み先行の順序

- 今回、対象トピックが明確だった（sandboxing）にもかかわらず、最初に`llms-full.txt`全体をキーワードgrepし、後から`temp/sandboxing.txt`を全文読んで初めて重要な落とし穴（コンテナ内bubblewrapの`/proc`問題）を見つけた。grep先行だと「当たればラッキー」で、別のキーワードを引いていたら見逃していた可能性がある。
- 改善案（要検討）:
  - スキルの手順に「対象トピックの`temp/`個別抽出ファイルが既に存在する場合は、まずそれを全文読んでから、横断的な確認だけ`llms-full.txt`のgrepで補う」という順序を明記する。
