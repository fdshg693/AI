# Step 10(実装+実験): scripts/extract_log.py の実装と実データでの反復検証

> [09-experiment-extraction-needs.md](09-experiment-extraction-needs.md) の続き。Step9で洗い出した機能要件を初版として実装し、実データに対して繰り返し動かしながら仕上げる。「一度書いて終わり」にせず、実装そのものを検証ステップとして扱う。

## やること

Step9で洗い出した機能要件をもとに `scripts/extract_log.py` の初版を実装する。実装したら、Step1・3・7で得た実ログ（セッショントランスクリプト、hookログ、`--debug-file`出力）に対して実際に実行し、欲しい情報が取れているかを確認する。取れていない・過不足があれば機能を調整し、再実行する。この反復を、抽出結果を`aim` CLIに渡した要約が実用的な質になるまで続ける。

## 決定事項・注意点／落とし穴

| 決定                                                                                                                                                                     | 理由                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| このステップでは初版実装で終わらせず、Step1・3・5・7の実データに対して最低1回は実行して結果を確認し、必要なら機能を追加してから完成とする                                | ユーザー指摘「実際にスクリプト実行・ログ確認などを行っていく中で、スクリプト化すべきものが新たに見えてくるはず」に対応するため。想像だけで仕上げない                          |
| `extract_log.py`は抽出専用とし、要約自体は行わない。要約は`aim` CLIへパイプ/ファイル渡しする2段構成として`SKILL.md`側の手順に明記する                                    | スクリプト内でOpenRouter呼び出し等を実装すると`aim-cli`スキルと責務が重複し、APIキー管理等の余計な複雑さを持ち込むため                                                        |
| 抽出結果の要約に`tools/aim-use/aim-summarize`（リポジトリ全体をSQLiteに要約蓄積するツール）は流用しない                                                                  | 用途がリポジトリ全体のファイル単位インデックス作成であり、「その場で抽出した断片を単発で要約する」という今回のユースケース（`aim-cli`の単発呼び出しモデル）とは合致しないため |
| 抽出スクリプトの出力先はスキル利用者の作業ディレクトリ配下の一時ファイルとし、書き出したパスを標準出力に明示する                                                         | `claude-code-docs`スキルの`output/temp/`パターンを踏襲し、後続で`aim`コマンドに渡す際にパスを追跡しやすくするため                                                             |
| Step9で洗い出せなかった要件（実行してみて初めて気づいたもの）が見つかった場合は、このステップの中で機能追加として吸収し、Step9のファイルを事後的に書き換えることはしない | 実験ステップは「その時点での仮説」の記録であり、後から答え合わせのために改変すると実験ステップの本来の意味（結果を踏まえて次を書く）が失われるため                            |
