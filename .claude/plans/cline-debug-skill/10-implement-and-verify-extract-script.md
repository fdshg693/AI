# Step 10(実装+実験): scripts/extract_log.py の実装と実データでの反復検証

> [09-experiment-extraction-needs.md](09-experiment-extraction-needs.md) の続き。Step9で洗い出した機能要件を初版として実装し、実データに対して繰り返し動かしながら仕上げる。「一度書いて終わり」にせず、実装そのものを検証ステップとして扱う。

## やること

Step9で洗い出した機能要件をもとに `scripts/extract_log.py` の初版を実装する。実装したら、Step1・3・7で得た実ログ（`cline.log` / `hub-daemon.log` / `hooks.jsonl` / セッションJSON / `--json` 出力）に対して実際に実行し、欲しい情報が取れているかを確認する。取れていない・過不足があれば機能を調整し、再実行する。この反復を、抽出結果を `aim` CLIに渡した要約が実用的な質になるまで続ける。

## 決定事項・注意点／落とし穴

| 決定                                                                                                                                                                     | 理由                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| このステップでは初版実装で終わらせず、実データに対して最低1回は実行して結果を確認し、必要なら機能を追加してから完成とする                                                | 「実際にスクリプト実行・ログ確認などを行っていく中で、スクリプト化すべきものが新たに見えてくる」ことを前提にするため。想像だけで仕上げない         |
| `extract_log.py` は抽出専用とし、要約自体は行わない。要約は `aim` CLIへパイプ/ファイル渡しする2段構成として `SKILL.md` 側の手順に明記する                                | スクリプト内でOpenRouter呼び出し等を実装すると `aim-cli` スキルと責務が重複し、APIキー管理等の余計な複雑さを持ち込むため                           |
| 199MB級の `hub-daemon.log` のような巨大ファイルを既定で全部は読まない設計にする（直近N件・時刻範囲の指定を前提とし、全件走査は明示指定時のみ）                           | Step1・9で確認した実サイズに基づく現実的な制約。巨大ファイルの全件走査は時間も出力も非実用的なため                                                 |
| 抽出スクリプトの出力先はスキル利用者の作業ディレクトリ配下の一時ファイルとし、書き出したパスを標準出力に明示する                                                         | `cline-docs` スキルの `output/temp/` パターンを踏襲し、後続で `aim` コマンドに渡す際にパスを追跡しやすくするため                                   |
| Step9で洗い出せなかった要件（実行してみて初めて気づいたもの）が見つかった場合は、このステップの中で機能追加として吸収し、Step9のファイルを事後的に書き換えることはしない | 実験ステップは「その時点での仮説」の記録であり、後から答え合わせのために改変すると実験ステップの本来の意味（結果を踏まえて次を書く）が失われるため |
