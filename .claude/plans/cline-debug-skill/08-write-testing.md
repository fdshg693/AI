## やること

Clineの設定・hooks・スキル変更が「実際に効くか」を安全に確認するためのテスト手法として、Cline CLIによる分離テスト（`--data-dir` 分離・`--auto-approve false` ・ `--json` ・ `--worktree`）と、SDK経由実行の位置づけ・使い分けをまとめた `testing.md` を作成する。SKILL.mdの決定表から `testing.md` へのリンクを実体化する。

## 決定事項・注意点／落とし穴

| 決定                                                                                                                                             | 理由                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 分離テストの手順は、Step7で実際に動作確認したコマンドをそのまま載せる（ドキュメントの組み合わせ推測だけに基づく手順は載せない）                  | 「動くはず」ではなく「実際に動いた」手順を載せることが、このスキルの核心要件のため                                                                        |
| `--data-dir` 分離で分離されるもの／されないもの（プロジェクト側の `.cline/` 配下はカレントディレクトリ基準で別問題、等）を実測結果込みで明記する | Claude Code版Step7で「`CLAUDE_CONFIG_DIR` はユーザースコープしか分離しない」という誤解しやすい落とし穴が実測されており、Clineでも同種の思い込みを防ぐため |
| `--key` やAPIキーの実値は一切書かず、認証の回避策は環境変数での指定方法のみ記載する                                                              | `cline-cli-use` の「秘密情報を履歴・ログに残さない」方針に従うため                                                                                        |
| SDK経由の節は、CLIとの違い（設定の共有範囲、キーの渡し方、ステートレス性）の要点に絞り、SDK自体の詳細は `cline-sdk-docs` への参照に留める        | 一次情報の細部は既存スキルへ譲るという[00-overview.md](00-overview.md)の方針どおり                                                                        |
