## 決定事項・注意点／落とし穴

| 決定                                                                                                                                                       | 理由                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| ログ仕込みテンプレートは、Step3で実際に動作確認できたものだけを載せる（ドキュメントの記述だけを根拠にした未検証のテンプレートは載せない）                  | 「動くはず」ではなく「実際に動いた」テンプレートを載せることが、このスキルを「単なる参考ドキュメントに留めない」ための核心的な要件のため |
| Windows特有の罠の節は、Step3で実際に再現できたものを優先し、再現しなかった／確認できなかった項目はその旨を明記した上でドキュメント由来の情報として区別する | 実地検証と伝聞情報を混同しないため。実装者が原因切り分け時にどちらの情報かを判断できるようにする                                         |
| イベント名・入出力契約・ファイル配置の記述はClineの実機検証結果のみを根拠にし、Claude Codeのhook仕様（`writing-hooks`相当）からの類推を一切書かない        | `cline-docs`スキルの「公式ドキュメントにない挙動を他のエージェントの仕様から類推しない」という注意に準拠するため。両者のhook機構は別物   |
| ドキュメントにイベントがあってもCLI単発実行で発火確認できなかったものは、「CLI単発実行では未確認（TUI/拡張が必要な可能性）」として一覧に残す               | 読み手が「このhookが発火しない＝壊れている」と誤判断するのを防ぐため                                                                     |
