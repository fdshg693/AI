# Step 4: VM側保持期間・運用ドキュメント・検証

## やること

ローカル同期が安定した後にVM側Lokiの保持期間を設定し、同期済みデータを削除できる運用へ移行する。初回同期から障害復旧までをREADMEに整理し、実データで取りこぼし・重複・集計結果を検証する。

## 読むべきファイル・実行推奨Grep

**保持期間設定の影響を確認するため（優先度: 高）**

- 読む: `tools/infra/ai-logs/docker/loki-config.yaml` — 現行schema・filesystem構成と追加設定の位置
- 読む: Step1の保持期間調査結果 — Loki 3.5.0に適用可能なcompactor/retention設定と削除タイミング
- Grep: `retention|compactor|delete|schema_config` — 設定漏れや既存記述との競合

**運用手順の影響範囲を確認するため（優先度: 高）**

- 読む: `tools/infra/ai-logs/README.md` — 初期構築、再デプロイ、SSH、Grafanaトンネルの既存手順
- 読む: `tools/infra/ai-logs/justfile` — deploy、logs、stats等の既存レシピ
- 読む: `.gitignore` — ローカルDB・状態ファイルの除外確認

**検証方法を確認するため（優先度: 中）**

- 読む: `tools/infra/ai-logs/scripts/verify_pipeline.sh` — 合成ログの送信・確認
- 読む: `tools/infra/ai-logs/scripts/verify_client.sh` — 実クライアントの送信確認
- 実行推奨: `just stats` — 保持期間変更・運用開始後のVMリソース確認

## 決定事項・注意点／落とし穴

| 決定                                                                                 | 理由                                                                                             |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 保持期間の短縮は、ローカルDBの最終成功同期時刻とバックフィル範囲を確認してから行う   | 未同期のログをVMから先に削除すると復旧不能になるため                                             |
| 保持期間設定のデプロイ後は、合成ログと実クライアントログの両方で検索・同期を確認する | Collector→Lokiの取り込み成功だけでは、ローカルダンプのページング・保存・集計まで保証できないため |
| 同期を数回失敗させた後に再実行し、取りこぼしなし・重複なしを検証する                 | 実運用で最も重要なチェックポイントと冪等性を確認するため                                         |
| ローカルDBはVMのバックアップ代替ではないとREADMEに明記する                           | ローカルマシン障害時の復旧や別端末利用には別途バックアップ設計が必要なため                       |
| Lokiの外部3100番ポート公開や認証無効化は行わない                                     | 現行のOTLP認証・Grafana非公開というセキュリティ方針を崩さないため                                |

## `.claude/rules` 更新ポイント

新規`.claude/rules/ai-logs-local-dump.md`を作成する。フロントマターは以下とし、本文は実装後の実際のコマンド・データ配置に合わせて確定する。

```markdown
---
paths:
  - "tools/infra/ai-logs/**"
---
```

記載する規約は、生成ログDBをコミット・外部同期しないこと、Lokiを安易に外部公開しないこと、保持期間短縮前に最終同期状態を確認すること、同期処理のチェックポイントと重複排除を壊さないこととする。
