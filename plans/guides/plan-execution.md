# プラン実行時

プランを読み込んで実装を進めるフェーズと、進捗の記録・完了後の後片付け。

## 実行中に必ず行うこと

各ステップの開始・中断・完了時に、次をその場で更新する。セッション終了時にまとめて記録しない。

1. 実行中のステップのfrontmatter `status` を [plan-writing.md](plan-writing.md) の値へ更新する。
2. `00-overview.md` がある場合は、overviewのfrontmatter `status` と、frontmatter直下にある「実装ステータス」の`- [ ]` / `- [x]`を同時に更新する。
3. `depends_on`がある場合は、各参照先とコメントに書かれた完了条件を確認してから着手する。依存関係を変えるときは、相手プランの`depends_on`/`blocks`と`order`も同時に更新する。
4. 予定外の事実が分かった場合は、影響を受けるプランの「やること」「触るファイル」「決定事項」「注意点」「実行順」を先に直接更新する。後続ステップ・後続タスクへの引継ぎをprogressへ書いて済ませない。
5. 初版は `snapshot/` に凍結済みなので、親フォルダ側のプランは古い記述の削除・全面改稿を含めて自由に書き換えてよい（`snapshot/` は編集しない）。変更したプランには「実行中に判明した変更」または「計画との差分」節を残し、変更の要約と更新箇所を1〜2行で明示すると追いやすい。
6. 調査の生データ、実装メモ、差分の詳細な根拠だけを `{plan-name}/progress/` 配下に記録する（書き方は [progress.md](progress.md)）。progressは詳細な記録であり、後続作業の正本にはしない。単一ファイル完結プランは `progress/` を持たず、1〜2行の差分を本体の「計画との差分」節に残す。

`status`・チェックボックス・依存関係を更新したら `lint_plans.py`（[plan-writing.md](plan-writing.md) の「整合性チェック」参照）で整合を確認する。

progressフォルダは実行開始時点では空（または未作成）でよい。ただし、**プランを完了する前には必ず完了記録を書く**。完了した範囲・検証結果・計画との差分の有無を記録し、差分がなければ「差分なし」と明記する。置き場所は次のとおり。

- フォルダ方式: 最終ステップのprogressの `## 完了記録` 節、または `progress/99-completion.md`
- 単一ファイル完結: プラン本体末尾の `## 完了記録` 節

## 完了後の後片付け

全ステップが `implementing-done` になり作業が完了したら、そのプランフォルダ／ファイルは通常不要になる。`depends_on`または`blocks`で未完了プランとつながる場合は、依存プラン群がすべて完了するまで削除を保留する。完了時は次の4点を後片付けとして行う。

1. 完了記録（上記）に完了範囲・検証結果・差分の有無を記録する。
2. 全ステップのfrontmatterを `implementing-done` にし、`00-overview.md` があればoverviewのfrontmatter `status` と「実装ステータス」チェックボックスを完了へ更新する。
3. `depends_on`/`blocks`で参照される未完了プランがなければ、プランファイル自体を削除する（`00-overview.md` + ステップファイル群の場合はそのプランフォルダ一式 — `snapshot/`・`rough/`・`progress/` を含む — 、単一ファイル完結プランの場合はそのファイル単体）。依存プラン群が残る場合は削除を保留する。
4. 削除に伴い、他の変更済みファイル中にそのプランファイルへの参照が残っていないか確認し、残っていれば依存関係を対で解消してから除去する。

実行中（`status: implementing-*` の間）は、他ファイルからプランファイルを参照するのは意図した使い方であり、むしろ進捗のトラッキングのために望ましい。既に完了扱いになっている過去の既存プランを遡って削除する必要はない。
