# Claude Code でのステップの進め方（任意導入）

[plan-writing.md](plan-writing.md) の「進め方とTODO化」で各ステップに書く「進め方」を、Claude Code のサブエージェント・スキルで具体化するときのメニュー。導入先にあるサブエージェント・スキルに合わせて取捨選択し、`plans/AGENTS.md` の「導入先固有の運用」節へ書き写して使う。Claude Code を使わない導入先ではこのファイルを削除してよい。

ここに出てくるスキル名（`proposing-flow`、`claude-cli-use`、`writing-*`、`task-tracker`）はテンプレートの元リポジトリにあったもので、導入先には無いことが多い。無ければ同等のものに読み替えるか、その行を書き写さない。

## 実行主体の選択

| 実行主体                                  | 使う場面                                                                                                            | 方法                                                                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| メインエージェント                        | ユーザーとの対話・判断を要する作業、後続ステップ全体の前提になる調査、1〜2ファイルで分割コストの方が高い作業        | そのまま実行                                                                                                      |
| 読み取り専用サブエージェント（`Explore`） | 既存パターンの有無をgrepで洗い出すだけの軽量なコードベース調査。設計判断を伴わない                                  | Agent tool `subagent_type: Explore`。必要なら `model: haiku` でコスト低下                                         |
| 汎用サブエージェント（`general-purpose`） | 独立して並行実行できる実装単位・書き込みを伴わない検証（レビュー・テスト結果確認）。resume して継続作業させたい場合 | Agent tool `subagent_type: general-purpose`。同時に複数体が同じファイルへ書き込むなら worktree isolation を要する |
| ステップ分割の提案用サブエージェント      | プラン立案時、ステップ分割と実行主体の提案が欲しいとき                                                              | 例: `proposing-flow` スキル経由で `flow-proposer` を呼ぶ（読み取り専用・提案のみ）                                |
| Claude CLI ワンショット                   | 大量の読み取り・重い独立タスクをメイン会話のコンテキストを汚さず実行したいとき                                      | 例: `claude-cli-use` スキル。タスク難度で Sonnet/Haiku を選ぶ                                                     |

サブエージェントは真っ新なコンテキストで始まる（メイン会話の文脈・`CLAUDE.md` 等のプロジェクト指示を知らない前提）。委譲時のプロンプトには必要な前提・出力フォーマットを明示する。委譲先には判断させず、決定事項の採否はプランを書く側が行う。

## ステップ種別ごとの推奨

| ステップ種別       | 実行主体                                                                                                                                                                        | TODO化                                                                                     | 使えるスキルの例                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------- |
| 立案（概要）       | ステップ分割に迷えば提案用サブエージェントに提案させ、採否はメインで決める                                                                                                      | 概要のステップ一覧の各項目を1 TODO にする                                                  | `proposing-flow`                                    |
| 調査               | Web調査（WebSearch/WebFetch）はメイン。既存パターンの有無確認だけなら `Explore`（+`model: haiku`）。重いドキュメントの一括読み込みは CLI ワンショット                         | ステップ全体を1 TODO。要約をプランに残し、後続ステップを更新してから完了                   | `claude-cli-use`                                    |
| 実装               | 後続の前提になるコア実装はメイン。ファイル非依存で分かれる単位は `general-purpose` に並行委譲（同じファイルに書くなら worktree isolation）。レビュー・テスト確認は読み取り専用 | 触るファイル群を「1項目 = 1コミット/1レビュー単位」で小分け。委譲単位は戻りを受けて完了   | `writing-rules`、`writing-subagents`、`writing-workflows` |
| 単一ファイル完結   | メイン単独。分割の調整コストの方が高い                                                                                                                                          | 「やること」1行を1 TODO                                                                    | `writing-rules`                                     |

## TODO化

- **1セッションで完結する小機能**: ステップの「やること」1行をそのまま TodoWrite 等の1項目にする。サブエージェントを跨ぐ場合も、メインエージェント側でステップ完了をマークする。
- **複数セッションをまたぐ・一時中断が前提の機能**: 例: `task-tracker` スキルで `tasks/{task-name}/CURRENT.md` に現状・次にやることを残す。ステップの完了マークはプラン側（overview のチェックボックス）、進行中の細かい現状は `CURRENT.md` 側、と棲み分けて二重管理にしない。`CURRENT.md` の関連ファイル節からプラン・progress へリンクを張ると再開時に辿りやすい。
- **サブエージェントに委譲したステップ**: 委譲単位を1つのTODO項目にし、戻り（結果）を受けて完了マーク。並列で複数体を走らせる場合は worktree isolation の要否もTODOに添える。

## プランへの書き方の例

各ステップファイルの「進め方」節に1〜3行で書く。

```markdown
## 進め方

- **実行主体**: 既存実装の有無確認は `Explore`（`model: haiku`）に委任。Web調査はメインで行う。
- **TODO化**: ステップ全体を1項目。要約を本プランに残し、Step2 を更新してから完了マーク。
```
