# templates/planner

実装前に「プラン」を書く運用を、他プロジェクトの `.claude/` にそのままコピーして導入するためのテンプレート。

## 構成

```
.claude/
  rules/
    always.md   # 常時ロード。「プランを求められたら plans/README.md を見る」と一言で誘導するだけ
    plans.md    # .claude/plans/** にパススコープ。プラン運用の要点サマリ
    rough.md    # .claude/rough/** にパススコープ。ラフプラン運用の要点サマリ
  plans/
    README.md   # 本体。プランに書くべき5点とステップ分割の目安を定義
    references/ # 実例4本（overview / 事前調査ステップ / 実装ステップ / 単一ファイル完結）
  rough/
    README.md   # 本体。ラフプラン（自由形式・任意）の使いどころと詳細プランへの移行方法を定義
    references/ # 実例1本（同じ架空機能で、詳細プランになる前の書き殴り方を示す）
```

複雑なタスクでは、詳細プラン（`.claude/plans/`）を書く前に、自由形式のラフプラン（`.claude/rough/`）で方針を練ってもよい。シンプルなタスクではラフプランを経由せず、直接詳細プランを書く。

## この構成が有効な理由

- **プランが毎回散らばる問題を、フォルダ構造で型にはめる**。書く場所（`.claude/plans/`）と書式（README.md の5点フォーマット）を固定することで、プランごとに粒度や項目がバラつかず体系的に積み上がる。
- **スキルだと「呼び出さないと使われず忘れられる」が、rules は強制的にロードされる**。`always.md` が薄いトリガーとして常時読み込まれ、`plans.md` は `.claude/plans/**` を触る瞬間に自動でロードされるため、意識しなくても運用が徹底される。
- **メンテコストが低い**。本体ロジックは `plans/README.md` 1箇所に集約し、rules 側は要点＋参照リンクのみを持つ。方針を変えるときも直す場所が少ない。

## トレードオフ

条件分岐やモデル選択、承認フローの自動化のような高度な制御はできない、素朴な仕組み。その代わり導入コストがほぼゼロ（フォルダをコピーするだけ）で、最小限の設定でプラン作成をクリアに保てる点を優先している。
